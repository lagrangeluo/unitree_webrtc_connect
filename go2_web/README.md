# Go2 本机 Web 控制台

面向 macOS、Go2 Air、固件 1.1.15 的横屏遥控页面。提供机器人视频、机器狗跟随视角与实时体素地图、运动状态、普通/AI 模式切换、起身/趴下/平衡站立，以及双模拟摇杆。界面参考手机遥控应用的功能布局，非宇树官方产品。

## 启动

在含 `pyproject.toml` 的项目目录执行：

```sh
source venv/bin/activate
python -m pip install -r go2_web/requirements.txt
# 可选：不设置 UNITREE_ROBOT_IP 时，点击「连接机器人」会在局域网组播自动发现 Go2
# export UNITREE_ROBOT_IP='你的机器人IP'
export UNITREE_ROBOT_SN='你的机器人序列号'   # 固件 1.1.15+ 自动发现必需
read -s 'UNITREE_AES_KEY?请输入设备 AES 密钥: '; echo
export UNITREE_AES_KEY
python -m go2_web
```

机器狗每次开机 IP 可能变化，建议不设 `UNITREE_ROBOT_IP`，由服务在连接时自动发现（与手机 App 相同的 `231.1.1.1` 组播查询，约 3 秒）。**Go2 固件 1.1.15 及以上只回应带序列号的定向查询，必须设置 `UNITREE_ROBOT_SN`**（序列号可在手机 App 设备信息中查看），否则一台也发现不了；序列号属于敏感信息，不要写进仓库。若路由器禁止组播或 Mac 处于访客网络导致发现失败，再手动设置 IP。

`read -s` 为 macOS 默认 zsh 写法，输入不显示、不将密钥写入历史。已设置环境变量时，无需重复输入。

浏览器打开 **http://127.0.0.1:8765**，点击「连接机器人」。服务启动不会自动连接或执行运动。AES 密钥仅保留在服务进程环境中，不发送给浏览器。服务仅监听本机，限制 Host/Origin，单个控制页面；不要将其通过代理暴露到公网。

需要 iPad 等同一局域网设备访问时，用 `python -m go2_web --lan` 启动，终端会打印 `http://<局域网IP>:8765`。此模式无鉴权，同一网络内任何设备都能控制机器人，仅在可信网络使用；仍只接受私有网段 IP 或 `.local` 主机名，并拒绝跨站请求。新打开的页面会接管控制，旧页面自动断开并锁定。

## 操作顺序

1. 关闭验证脚本、宇树 App 等占用连接的客户端，确认 Mac 与 Go2 同局域网。
2. 点击连接，等待状态、视频、点云到达。无数据或过期会明确标识，不使用模拟数据。
3. 确认空旷场地、保留可用遥控器，然后点击「控制已锁定」解锁。
4. 连接成功后即可切换「普通运动」或「AI 运动」，也可点击起身、趴下和平衡站立；这些操作都需要确认，不需要先解锁摇杆。机器人返回成功后才更新模式，姿态/模式操作后自动锁定。进入 AI 模式后仍可切回普通模式。
5. 手动驾驶区的速度滑动条按比例缩放三轴指令，默认 50%，范围 10%–100%；后端仍保留绝对速度上限。普通运动或 MCF 模式下再次解锁，左杆控制前后与侧移，右杆控制转向。Go2 固件 1.1.15 可能报告 `mcf`；此时直接使用 MCF 接口，不能强行切换 `normal`。100% 时前后上限 0.60 m/s、侧移 0.30 m/s、转向 1.00 rad/s；默认 50% 时分别为 0.30、0.15、0.50。面板显示缩放后的平移/转向指令和当前限速，实际速度由机器人反馈确认。
6. 键盘：↑/↓ 前进后退，←/→ 左右旋转，A/D 左右平移。需在普通模式解锁后按住，松键归零，支持组合按键；相反方向同时按下时归零。
7. 松手归零；「停止运动并锁定」或空格键尝试停止。页面失焦/隐藏/关闭时锁定，后端在 350ms 未收到摇杆刷新时尝试停止。Ctrl+C 退出服务时也清理连接。

## 实现与限制

浏览器通过本机 WebSocket 接收数据；Python 使用上游 WebRTC 库连接 Go2。视频转 JPEG（最多约 10fps、960×540）。三维感知移植自本工作区 `unitree_ui`，全部脚本、模型、纹理、HDR 环境和 WASM 均使用本地资源：

- `src/ui/scene/scene.ts` → `static/three/scene.js`：Z 轴向上，70° 视场角；相机位于机身后方 1.2 米、上方 1 米，朝机器人前方 4 米，随航向旋转，采用相同雾效、灯光和 HDR 环境。默认跟随模式锁定轨道操作，按钮或双击切换可旋转、平移、缩放的总览模式。
- `src/workers/voxel-worker.ts` 和 `src/ui/scene/voxel-map.ts` → `static/three/voxel-worker.js`、`voxel-map.js`：原始 `voxel_map_compressed` 压缩数据保留并发给浏览器 Worker，由相同的 `libvoxel.wasm` 生成带 UV 的三角网格，使用 `axisColor4.png` 和最近邻采样。按 `resolution` 缩放、按 `origin` 平移；地图不受调试点云 16,000 点采样上限影响。每帧替换局部地图，释放旧几何体，待处理数据仅保留最新帧。
- `src/ui/scene/robot-model.ts` → `static/three/robot-model.js`：相同 Go2 模型、半透明材质、隐藏连杆、关节轴和雷达旋转。优先使用 `rt/utlidar/robot_pose` 中的完整位姿；该话题两秒未更新时回退到运动状态的位置和 IMU 四元数，保留机身 Z 偏移 −0.3 米。

三维感知显示机器人推送的实时局部体素地图。移植源码及 Three.js 的许可证位于 `static/three/`。

## 实时建图与导航（最小系统）

右侧「实时建图」面板替代了原来的原始 3D 点云调试视图，实现在 `slam.py`（仅依赖 numpy）：

- **位姿与漂移校正**：Go2 Air 没有 `rt/utlidar/robot_pose`，位姿回退到 `rt/lf/sportmodestate`（腿式运动学 + IMU，与体素地图同一 `odom` 坐标系）。它的偏航会随时间缓慢漂移，表现为旧地图与当前扫描的夹角越来越大（重影）。因此每次写入地图前，先把本帧障碍扫描与已有地图做相关性扫描匹配：似然场 + 双线性插值，±2° / ±0.15 m 搜索，只用落在已观测区域的点，并按两次建图之间的里程计运动量加一个小先验，累积得到「地图 = R(Δθ)·里程计 + t」的修正。规划、导航和地图上的红色箭头都用修正后的位姿，面板顶部显示累计校正量。第一帧会把体素格点对齐到栅格中心（≤ 2.5 cm 的一次性平移）。长直无特征走廊里，沿走廊方向的距离无法由墙面确定，只能沿用里程计，横向位置与朝向仍会被纠正。站起、趴下或切换模式时若状态估计器整体重置，终端会打印「位姿跳变」，这种大跳变超出匹配范围，需要清空地图重建。三维感知视图仍使用机器狗原始的里程计坐标。
- **建图**：把每帧体素累积进 5 cm 的 2D 占据栅格（60 m × 60 m，以开机原点为中心）。地面取机身附近体素最密的高度层，再按 1 m 分块用各列最低点得到地面底部；实测 Go2 的地面在体素地图里约有 25 cm 厚（反光/噪声累积），因此只把离地面底部 0.30–0.70 m 的体素算障碍，对应三维视图里的黄色与橙色，绿色（地面噪声）和紫/红色（高于机器狗）都不参与建图；低于约 30 cm 的矮障碍可能检测不到。地面体素和「机身到每个方向最近障碍」的射线把格子判为空闲，因此移走的障碍会被擦除；log-odds 有上下限，已确认的格子不再变化。机器狗静止时每 0.8 s 才刷新一次，地图分类没变就不重新下发。地图只在本次连接内有效，断开、重连或点「清空地图」即丢弃。
- **规划**：障碍膨胀 0.30 m（紫色区域），离障碍 0.70 m 内加代价让路径走通道中间；在 10 cm 栅格上跑 A*，再做保持净空的捷径平滑。只走已观测为空闲的格子，目标在未探索区域、障碍上或离障碍太近会直接拒绝并提示原因。
- **跟随**：纯跟踪（前视 0.5 m），最高 0.40 m/s、0.8 rad/s，前进时不低于 0.15 m/s（再低 Go2 基本只原地踏步），弯道仅温和减速；偏差大于约 50° 时原地转向，到达 0.12 m 内后转到目标朝向。导航**直接下发 `Move` 速度指令，不经避障服务**（与避障开关无关），只靠实时重规划和下列停车检查避障。

使用：解锁控制 → 点「➤ 导航目标」→ 在地图上按下设置位置、拖动设置朝向、松开发送（单击则朝向沿机器狗到目标的方向，Esc 取消）。导航时「✕ 取消导航」、停止按钮、空格、拨动摇杆、锁定控制、页面失焦都会立即停止。

自动停车与失败条件：车头前方 0.35 m + 0.5 s × 当前速度（0.40 m/s 时为 0.55 m，宽 ±0.21 m）内有障碍即停车并重新规划，受阻 12 s 失败；原地转向需 0.40 m 半径内无障碍；里程计超过 0.5 s 或点云超过 1 s 未更新即停车，更久则失败；25 s 内没有沿路径前进则失败；页面 350 ms 心跳丢失即停止。

已知限制：激光看不到玻璃、镜面和过低的障碍，地图上会显示为可通行；里程计漂移会让大范围地图出现重影；动态障碍只能靠重规划应对，务必低速、在空旷场地并保留遥控器测试。

姿态为 Go2 上游接口，Air 固件是否支持需要实机验证。返回失败或超时会提示，不视作成功。移动指令以 10Hz 发送、限速；不以请求应答证明实际移动，需观察实机和状态。软件停止不是硬件急停；机器人或网络断开后无法保证停止送达，必须实测机器人自身失联保护。

三维感知使用 WebGL；下方调试点云使用 Canvas 软件投影。页面/后端测试不执行实机动作。已完成的离线检查不代表视频、点云或运动接口已通过实机验收。

## 排障

- 缺少 `aiohttp`：在项目 venv 执行上方依赖安装。
- 连接失败：确认 IP、32 位 AES 密钥及端口 9991 可达，允许终端的 macOS 本地网络权限。
- 已有页面：关闭其他控制页面后刷新；只允许一个控制连接。
- 视频或点云等待：确认机器人支持并提供该通道；单个媒体源失败不能通过假数据替代验证。
- 控制未解锁/模式未知：先建立连接，再解锁并切换普通模式；若设备拒绝，请检查其实际运动模式和固件支持。

三维感知：默认跟随机器人，点击「切换总览」或双击画布后，可左键旋转、右键平移、滚轮缩放，再次切换返回跟随。实时建图：默认俯视且 +X（开机朝向）朝上；左键拖动旋转、右键拖动平移、滚轮缩放，重置视角恢复俯视。白色 O 标记本次开机的里程计零点，红/绿/蓝轴指向 +X/+Y/+Z，轴长 1 米；红色箭头为机器狗当前位姿，黄色点为本帧过滤后的障碍扫描，绿色线为规划路径，紫色箭头为导航目标。

```sh
venv/bin/python -m compileall -q go2_web

```
